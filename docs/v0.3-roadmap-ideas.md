# Đề Xuất Lộ Trình & Ý Tưởng Mới Cho NightOwl Evals (v0.3.0+)

Tài liệu này ghi lại các ý tưởng mở rộng tiềm năng cho các phiên bản tiếp theo của **NightOwl Evals** (`@hoanghainh/nightowl-evals`), sau khi phiên bản `v0.2.0` đã đạt trạng thái Production-Ready.

---

## 1. Trạng thái hiện tại của Lộ trình (Roadmap Status)

### Đã hoàn thành (v0.1.0 - v0.2.0)
* **P0**: Cross-platform process tree killing, Inline secret filter, Lệnh `nightowl doctor`.
* **P1**: Lệnh `nightowl prune` & SQLite retention, Hỗ trợ hook manager (Husky, Lefthook), Machine-readable outputs & CI Quality Gate (`--fail-on-rate`, `--output`, `--json`).

### P2 (đã hoàn thành)
* **Change 16 (`add-eval-test-runner`)**: Chạy kiểm thử tự động (unit tests) để verify eval thay vì chỉ tính textual overlap.
* **Change 17 (`add-direct-api-classify`)**: Hỗ trợ gọi phân loại trực tiếp qua LLM API key (không phụ thuộc `claude` CLI).

### Ideation v0.3 (18–24) — Done
Toàn bộ ý tưởng mục 2 dưới đây đã ship. Hướng tiếp theo: [`v0.4-roadmap-ideas.md`](v0.4-roadmap-ideas.md).

## 2. Các Ý Tưởng v0.3.0+ Ideation (đã chốt)

### Ý tưởng 1: Hỗ trợ Đa Agent / Trợ lý AI (Multi-Agent & Tool Agnostic) — Done
* **Bối cảnh**: Hiện tại NightOwl tích hợp sâu vào Claude Code (`.claude/settings.json`, PostToolUse hook).
* **Mở rộng**:
  - Hỗ trợ bắt snapshot từ các công cụ phổ biến khác: **Cursor, Windsurf, Cline, Roo Code, GitHub Copilot Workspace, Aider**.
  - Bổ sung cơ chế git-based fallback: Tự động so sánh staged diff với các session branch hoặc MCP server hook.
  - Thống kê đối đầu (Benchmarking Head-to-Head): Báo cáo so sánh tỷ lệ lỗi giữa các trợ lý AI trên cùng codebase (ví dụ: "Tuần qua: Claude Code cần dev sửa 12% edits, Cursor cần sửa 24% edits").

### Ý tưởng 2: Vòng phản hồi tự động tối ưu Rule (`nightowl optimize-rules`) — Done
* **Ý nghĩa**: Biến các lỗi đã được dev sửa thành rule hữu ích ngay lập tức.
* **Cách hoạt động**:
  - Phân tích các lỗi phổ biến nhất theo category (`convention`, `missing-context`).
  - Lệnh `nightowl suggest-rules`: Tự động tổng hợp và sinh đề xuất văn bản quy ước để dev đưa vào `CLAUDE.md`, `.cursorrules` hoặc file quy tắc dự án.
  - Ngăn ngừa AI lặp lại cùng một sai lầm trong các phiên làm việc tiếp theo.

### Ý tưởng 3: Tự động sinh bài kiểm thử hồi quy (Regression Test Synthesizer) — Done
* **Ý nghĩa**: Biến mỗi lần sửa lỗi AI thành tài sản test vĩnh viễn cho dự án.
* **Cách hoạt động**:
  - Khi một lỗi được đánh dấu `confirmed` (hoặc dev sửa code do AI viết sai), NightOwl có thể phân tích diff và tạo một test case hồi quy khung (ví dụ `test/regressions/eval-case-<id>.test.ts`).
  - Nhà phát triển có thể kiểm tra và commit test case này vào test suite của dự án.

### Ý tưởng 4: Giao diện TUI tương tác dòng lệnh (`nightowl review -i`) — Done
* **Ý nghĩa**: Giúp dev duyệt và phân loại lỗi nhanh hơn nhiều so với việc gõ ID từng lệnh.
* **Cách hoạt động**:
  - Chế độ dòng lệnh tương tác nhẹ (dùng ANSI escape chuẩn, không cần dependency ngoài):
    - Phím `↑` / `↓` để di chuyển qua danh sách lỗi.
    - Phím `Enter` hoặc `Space` để mở diff xem trước (có tô màu cú pháp `+` xanh, `-` đỏ).
    - Phím `c` để đánh dấu `confirmed`, `d` để `dismiss`, `r` để `reset`.
    - Phím `q` để thoát.

### Ý tưởng 5: GitHub Action đóng gói sẵn (`nightowl-evals-action`) — Done
* **Ý nghĩa**: Tích hợp CI/CD 1-click cho các team dùng GitHub Actions.
* **Cách hoạt động**:
  - Đóng gói composite action:
    - Chạy `nightowl report --json --fail-on-rate 25`.
    - Tự động post bảng tóm tắt "AI Coding Health Report" vào sticky comment của Pull Request.
    - Cảnh báo team khi một PR có quá nhiều code AI bị dev phải viết lại hoàn toàn.

### Ý tưởng 6: Xuất định dạng Benchmark chuẩn Quốc tế (SWE-bench / Promptfoo) — Done
* **Ý nghĩa**: Kết nối NightOwl với hệ sinh thái benchmark AI lớn hơn.
* **Cách hoạt động**:
  - Mở rộng lệnh `nightowl export`:
    - `--format jsonl` (mặc định hiện tại).
    - `--format swe-bench`: Xuất thành dataset tương thích format SWE-bench (base commit, problem statement, test patch).
    - `--format promptfoo`: Xuất cấu hình test cho framework promptfoo.

### Ý tưởng 7: Shell Autocompletion — Done
* **Ý nghĩa**: Trải nghiệm developer thân thiện, mượt mà khi dùng terminal hàng ngày.
* **Cách hoạt động**:
  - Lệnh `nightowl completion <bash|zsh|fish>` sinh mã completion script.
  - Gợi ý các subcommand (`init`, `doctor`, `prune`, `report`, `review`, `classify`, `eval`, `export`, `uninstall`) và đầy đủ các flag tuỳ chọn.
