## 2. Ưu tiên chính (v0.6 Core)

### Ý tưởng 1: Doctor sẵn sàng cho máy team (`deepen-doctor-team-readiness`) — #40 — Done
* **Bối cảnh**: `doctor` đã có health cơ bản; khi onboard 2–3 máy team, thiếu kiểm tra workspace discovery, hook file tool thực sự đọc, và “report readiness” (có failure/signal đáng tin).
* **Mở rộng**:
  - Kiểm tra monorepo workspace config khi có; cảnh báo discovery rỗng trên repo có `packages/*`.
  - Xác minh hook/agent marker mà tool đọc được (không chỉ file tồn tại).
  - Tóm tắt readiness: DB, failures non-dismissed, signals, privacy flags — vẫn local, fail-open.

### Ý tưởng 2: Windows local DX (`improve-windows-local-dx`) — #41 — Done
* **Bối cảnh**: Kill process group đã fix; còn edge path (`\`), quyền NTFS so với `0700`, và hook/shell trên Windows.
* **Mở rộng**:
  - Chuẩn hóa path end-to-end (store, report, workspace, hooks).
  - Fallback permission rõ trên NTFS; document giới hạn.
  - Fixture/test Windows hoặc mô phỏng đường dẫn Windows trong unit test.

### Ý tưởng 3: Siết vòng phản hồi rule (`tighten-rule-feedback-loop`) — #42 — Done
* **Bối cảnh**: Đã có `suggest-rules`, ghi apply, `rule-impact`, digest — nhưng trải nghiệm còn rời lệnh.
* **Mở rộng**:
  - Luồng document/CLI gắn label rule → cửa sổ impact → dòng digest/dashboard thống nhất.
  - Gợi ý bước tiếp theo sau `suggest-rules --write` (không gọi mạng).
  - Không tự sửa rules repo trừ khi user opt-in rõ.

### Ý tưởng 4: Làm sâu multi-agent adapters (`deepen-multi-agent-adapters`) — #43 — Done
* **Bối cảnh**: Một số agent vẫn best-effort (marker + parse generic); team nội bộ dùng nhiều tool cùng lúc.
* **Mở rộng**:
  - Fixture/adapter thật hơn cho tier tiếp theo; `doctor`/`init` kiểm tra sâu hơn.
  - Document giới hạn từng agent; giữ fail-open, không chậm agent.

## 3. Polish (v0.6 Secondary)

### Ý tưởng 5: Prune UX (`improve-prune-ux`) — #44 — Done
* **Ý nghĩa**: `prune` đã có; team cần ước lượng dung lượng trước khi xóa và profile retention rõ.
* **Cách hoạt động**: Dry-run báo số hàng/bytes sẽ xóa; retention profiles; tóm tắt vacuum sau prune.

### Ý tưởng 6: Mở rộng metrics theo workspace (`extend-workspace-metrics`) — #45 — Done
* **Ý nghĩa**: `#39` MVP chỉ lọc failure; `changedRate`/checks/signals vẫn full-window — dễ lệch khi `--fail-on-rate` + `--workspace`.
* **Cách hoạt động**: Tuỳ chọn scope checks (khi có path) và document rõ signals; cảnh báo khi gate + filter không cùng mẫu số.

### Ý tưởng 7: Gói share-out local (`local-team-share-pack`) — #46 — Done
* **Ý nghĩa**: Team cần gửi báo cáo đã redact cho nhau/offline mà không mở SaaS.
* **Cách hoạt động**: Lệnh/bundle zip local (report + digest + privacy profile); không network; không tên developer.

### Ý tưởng 8: Hiệu năng DB lớn (`large-db-performance`) — #47 — Done
* **Ý nghĩa**: Store lâu ngày làm `report`/`dashboard` chậm trên máy laptop.
* **Cách hoạt động**: Index/query budget, đo thời gian trong doctor hoặc flag debug; không đổi semantics báo cáo.
