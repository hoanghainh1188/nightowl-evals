# Đề Xuất Lộ Trình & Ý Tưởng Mới Cho NightOwl Evals (v0.7.0+)

Tài liệu này ghi các hướng mở rộng sau khi **v0.6 ideation (40–47)** đã Done và ship **`v0.6.0` / `v0.6.1`**. Phạm vi vẫn **open-core / local-first**: không telemetry; LLM tắt mặc định.

**Mục tiêu giai đoạn:** đóng điều kiện **giai đoạn 2** trong [`nightowl-evals.md`](nightowl-evals.md) — *có số liệu so model / rules và tỷ lệ lỗi lặp giảm rõ* — trên máy/CI local của 2–3 team; siết vận hành DB/config/share offline. **Chưa** SaaS / sync multi-repo / multi-tenant / dashboard team hosted (vẫn repo thương mại riêng).

Nguồn đánh giá: readiness còn ~85% ở Classification / Export–Eval / Team local surfaces ([`production-readiness.md`](production-readiness.md)); cổng giai đoạn 2 chưa có metric “lỗi lặp” first-class; `share-pack` mới xuất chiều một chiều; classify vẫn phụ thuộc LLM opt-in; thiếu config team local thống nhất và backup/restore.

## 2. Ưu tiên chính (v0.7 Core)

### Ý tưởng 1: Đo lỗi lặp / outcome giai đoạn 2 (`measure-repeat-failure-outcomes`) — #48 — Done
* **Bối cảnh**: Điều kiện qua giai đoạn 2 là “tỷ lệ lỗi lặp lại giảm rõ”; hiện có cluster + rule-impact nhưng chưa có metric/cohort first-class trên `report` / digest / dashboard để chứng minh cải thiện theo thời gian.
* **Mở rộng**:
  - Định nghĩa deterministic (local): cluster / fingerprint xuất hiện lại sau cửa sổ baseline; tỷ lệ repeat vs new trong `--since`.
  - Surface trên `report --json`, digest, dashboard; tuỳ chọn so hai cửa sổ (trước/sau rule hoặc hai mốc thời gian).
  - Không tên developer; không gọi mạng; document giới hạn khi fingerprint/agent thiếu.

### Ý tưởng 2: Config / profile team local (`add-local-config-profiles`) — #49 — Done
* **Bối cảnh**: Team 2–3 máy lặp lại flag (`--fail-on-rate`, privacy, prune profile, agents, workspace mặc định) qua README/CI copy-paste; dễ lệch giữa máy.
* **Mở rộng**:
  - File config local đã document (ví dụ `.nightowl/config.json` hoặc `nightowl.toml` ở root — chốt trong design): defaults cho report/CI gate, privacy, prune, digest window.
  - CLI đọc config khi flag CLI không truyền; `doctor` kiểm tra config hợp lệ; mẫu commit được (không secret) vs phần máy-local gitignore.
  - SHALL NOT sync remote / SHALL NOT gửi telemetry.

### Ý tưởng 3: Phân loại offline / heuristic mạnh hơn (`improve-offline-classification`) — #50 — Done
* **Bối cảnh**: Classification ~85%; LLM tắt mặc định → nhiều failure `unclassified`; team nội bộ ngại bật API key.
* **Mở rộng**:
  - Heuristic / rule-based classify (category từ diff shape, path, convention hints) chạy **mặc định offline**, không mạng.
  - LLM classify vẫn opt-in và có thể ghi đè / bổ sung confidence; không đổi nguyên tắc “LLM off by default”.
  - Báo cáo % classified-by-heuristic vs llm vs unclassified trong `report`.

### Ý tưởng 4: Vòng eval suite từ failure → so điểm (`tighten-project-eval-loop`) — #51 — Done
* **Bối cảnh**: Export / eval / eval-compare / suggest-regressions đã có nhưng trải nghiệm còn rời; giai đoạn 2 cần “so model có số” thành thói quen tuần, không chỉ power-user.
* **Mở rộng**:
  - Luồng document/CLI: cluster hoặc review confirmed → suite JSONL gắn label → `eval` / `eval-compare` → dòng digest/dashboard (delta vs baseline).
  - Gợi ý bước tiếp theo sau `export` / `suggest-regressions` (local, không mạng).
  - Không bịa test patch; giữ privacy profile khi xuất suite mang ra ngoài máy.

## 3. Polish (v0.7 Secondary)

### Ý tưởng 5: Import / merge share-pack local (`import-local-share-pack`) — #52
* **Ý nghĩa**: `#46` chỉ xuất gói; team offline cần **nhận** pack đã redact từ máy khác mà không mở SaaS hay copy tay từng file.
* **Cách hoạt động**: `nightowl share-pack --import` (hoặc lệnh `import-pack`) đọc archive local, kiểm tra manifest privacy, merge sự kiện/tổng hợp đã document (hoặc chỉ materialize report artifacts — chốt non-destructive trong design); không network; từ chối pack thiếu redaction bắt buộc.

### Ý tưởng 6: Backup / restore DB local (`add-db-backup-restore`) — #53
* **Ý nghĩa**: Laptop đổi / disk đầy / thử migration; hiện dựa vào copy file `.nightowl/` thủ công và `prune`.
* **Cách hoạt động**: `nightowl backup` / `restore` (hoặc `db backup`) tạo bản sao nhất quán (SQLite safe), liệt kê, khôi phục có xác nhận; tương thích Windows/macOS/Linux; không upload.

### Ý tưởng 7: Customer-report theo xu hướng (`deepen-customer-report-trends`) — #54
* **Ý nghĩa**: Báo cáo VI–JA đã có một cửa sổ; khách hỏi “tháng này hơn tháng trước?” cần so sánh đa cửa sổ trên máy, vẫn không tên dev.
* **Cách hoạt động**: Tuỳ chọn so N cửa sổ / baseline label; biểu đồ hoặc bảng delta trong Markdown/HTML local; tái dùng metric repeat (#48) khi có.

### Ý tưởng 8: Policy file cho CI gate (`add-ci-policy-file`) — #55
* **Ý nghĩa**: GitHub Action + `--fail-on-rate` đã có; monorepo cần policy theo workspace/agent nằm trong repo (reviewable) thay vì chỉ input workflow.
* **Cách hoạt động**: File policy đã document (YAML/JSON) mà Action/`report` đọc: threshold, since, workspaces, agents; `doctor` validate; lệch flag CLI vs policy → cảnh báo. Vẫn local/CI runner — không control-plane cloud.
