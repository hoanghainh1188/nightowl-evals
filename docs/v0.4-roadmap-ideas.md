## 2. Ưu tiên chính (v0.4 Core)

### Ý tưởng 1: Làm thật adapters đa agent (`harden-multi-agent-adapters`) — Done
* **Bối cảnh**: Change 18 đã có registry + Cursor/Claude chắc; Windsurf / Cline / Roo / Copilot Workspace / Aider chủ yếu marker config + parse generic.
* **Mở rộng**:
  - Adapter riêng (hoặc fixture thật) theo hook/CLI từng tool; document giới hạn từng agent.
  - `init`/`doctor` kiểm tra hook file thực sự được tool đọc (không chỉ ghi JSON marker).
  - Giữ fail-open, không chậm agent.

### Ý tưởng 2: Tín hiệu CI và review PR (`add-ci-pr-failure-signals`) — Done
* **Bối cảnh**: Product doc liệt kê test/build fail và comment review; Action hiện chỉ chạy `report` trên DB sẵn có.
* **Mở rộng**:
  - Ingest kết quả CI fail (log/JUnit/summary) gắn với commit/agent khi suy ra được.
  - Ingest hoặc map comment review PR (GitHub) thành tín hiệu/failure phụ — vẫn local hoặc chỉ dùng API khi user opt-in trong CI.
  - Không bịa `ai_content`; chỉ failure đầy đủ khi có snapshot/ghép hợp lệ.

### Ý tưởng 3: Vòng kín rule → eval → đo giảm lỗi lặp (`add-rule-impact-metrics`) — Done
* **Bối cảnh**: Đã có `suggest-rules`, `suggest-regressions`, `eval` / report theo category.
* **Mở rộng**:
  - Ghi “baseline” trước/sau khi áp rule (thời điểm, category, agent).
  - `nightowl report` (hoặc lệnh con) so tỷ lệ lỗi lặp / cùng category trong cửa sổ sau khi rule được đánh dấu đã áp dụng.
  - Phục vụ giai đoạn dùng nội bộ team: chứng minh rules thật sự giảm sai.

### Ý tưởng 4: Báo cáo chất lượng cho khách (`add-customer-quality-report`)
* **Bối cảnh**: Phân khúc outsource VN–Nhật cần báo cáo chất lượng AI; điểm khác biệt song ngữ VI–JA.
* **Mở rộng**:
  - Lệnh xuất báo cáo Markdown (và tùy chọn HTML đơn giản) từ dữ liệu local: tỷ lệ sửa, theo module/category/agent, xu hướng tuần.
  - Bản mẫu song ngữ Việt – Nhật (template local, không gọi mạng).
  - Không đưa tên dev; chỉ chấm AI.

## 3. Polish (v0.4 Secondary)

### Ý tưởng 5: Ghi rule an toàn vào file dự án (`add-suggest-rules-write`) — Done
* **Ý nghĩa**: Roadmap v0.3 mô tả đưa đề xuất vào `CLAUDE.md` / `.cursorrules`; hiện nghiêng stdout / `--output`.
* **Cách hoạt động**: `--write <path>` với marker NightOwl, không đè nội dung người dùng ngoài vùng marker; `--force` chỉ khi an toàn / đã xác nhận.

### Ý tưởng 6: SWE-bench export đủ harness hơn (`improve-swebench-harness`)
* **Ý nghĩa**: Export hiện best-effort; `FAIL_TO_PASS` / test patch còn trống.
* **Cách hoạt động**: Khi có regression fixture / stub từ `suggest-regressions`, điền harness fields tương thích hơn (vẫn không phải official SWE-bench dataset).

### Ý tưởng 7: Doctor và Action kiểm tra sâu hơn (`deepen-doctor-ci-checks`)
* **Ý nghĩa**: Giảm friction CI/team khi thiếu DB hoặc hook agent.
* **Cách hoạt động**: `doctor` kiểm tra hook đa agent đã cài; Action/docs hướng dẫn restore `.nightowl` artifact rõ hơn; cảnh báo sớm khi thiếu dữ liệu để `report`.

4. **Secondary** — write rules, SWE-bench harness, doctor/CI — xen kẽ khi Core ổn.
